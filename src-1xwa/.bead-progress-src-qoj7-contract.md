# Contract: zellij Save plugin state on timer

## Overview
Implement periodic automatic state saves for the Zellij plugin using the existing `RefreshTimer` infrastructure.

## Preconditions
- Zellij plugin is running
- StateManager is available
- Timer module is initialized

## Postconditions
- Plugin state is saved automatically at configured intervals
- Timer events trigger state saves
- Save errors are handled gracefully (no panics)
- Last save timestamp is tracked

## API Contract

### New Methods on OyaPlugin

```rust
impl OyaPlugin {
    /// Initialize auto-save timer with configured interval
    /// Returns Result with PluginError on failure
    pub fn init_auto_save(&mut self, interval_secs: u64) -> PluginResult<()>;

    /// Handle timer event and trigger save if needed
    /// Returns Result with PluginError on save failure
    pub fn handle_timer_event(&mut self) -> PluginResult<Option<String>>;

    /// Force immediate state save
    /// Returns Result with PluginError on save failure
    pub fn save_state_now(&mut self) -> PluginResult<()>;

    /// Get last save timestamp (if any)
    pub fn last_save_timestamp(&self) -> Option<u64>;
}
```

### New Fields on OyaPlugin

```rust
pub struct OyaPlugin {
    // ... existing fields ...

    /// Auto-save timer (optional)
    auto_save_timer: Option<RefreshTimer>,

    /// Last successful save timestamp (unix seconds)
    last_save_timestamp: Option<u64>,
}
```

## Behavior Specification

### Timer Initialization
- `init_auto_save()` creates a RefreshTimer with specified interval
- Minimum interval: 10 seconds (enforced)
- Default interval: 30 seconds if not specified
- Timer starts automatically after initialization
- Failure to create timer returns PluginError

### Timer Event Handling
- On `PluginEvent::Timer`, call `handle_timer_event()`
- Check if interval has elapsed using `is_tick_due()`
- If due, call `save_state_now()`
- Update `last_save_timestamp` on successful save
- Log save errors to status_message (don't panic)
- Return rendered UI or None

### State Save Operation
- `save_state_now()` uses StateManager to save current state
- Creates snapshot using `create_snapshot()`
- Calls `StateManager::save_state()`
- Updates `last_save_timestamp` on success
- Returns `Err(PluginError)` on failure with details
- Status message updated with "State saved at {timestamp}" on success

### Error Handling
- All save errors are captured, not panicked
- Status message shows: "State save failed: {error}"
- Timer continues running even after save failure
- No unwraps, no panics in any code path

## Configuration

### Default Settings
- Auto-save interval: 30 seconds
- Minimum interval: 10 seconds
- Maximum interval: 600 seconds (10 minutes)

### User Configuration (via Zellij config)
```json
{
  "auto_save_interval_secs": 30
}
```

## Integration Points

### Event Loop (plugin.rs)
```rust
PluginEvent::Timer => {
    self.handle_timer_event()?;
    self.render()
}
```

### Plugin Initialization (plugin.rs)
```rust
pub fn start(&mut self, info: PluginInfo) -> PluginResult<String> {
    // ... existing code ...

    // Initialize auto-save from config
    let interval = info.config
        .get("auto_save_interval_secs")
        .and_then(|v| v.as_u64())
        .unwrap_or(30);

    let _ = self.init_auto_save(interval);

    // ... rest of start() ...
}
```

## Invariants
1. Zero panics: all errors return Result
2. Zero unwraps: use ? operator or map_err
3. Timer state is always valid (Idle/Running/Paused/Stopped)
4. StateManager is always available (default() never fails)
5. Last save timestamp is only updated on successful save
